# 缓存模拟模型家族修复验证

日期：2026-10-16。基于提交 `0a08d93`，在现有隔离分支 `integration/kiro-reverse-2.1.0` 本地实现；未上线、未推送或修改 Sub2API。

## 已确认的修复

- 总缓存模式从四个具体版本的名单改为识别 Sonnet、Opus、Haiku 家族的数字版本，包括日期、latest、thinking 后缀。
- 本地模拟默认门槛：Sonnet 1024、Opus/Haiku 4096。这不是官方版本门槛或上游缓存遥测声明。
- 缓存内部规范化点号、横杠、大小写、首尾空白及 anthropic. 包装前缀；不改变发送到上游的模型名称或配置映射。
- 不同家族、版本、日期和思考后缀保留不同指纹。未识别家族、无效名称仍然不生成缓存。
- 比例浮动、旧前缀份额稳定、增量写入、5m/1h 拆分及旧模式保持原语义。
- 诊断中文/英文明确使用“模拟门槛”“未识别家族”表述。

## 验证结果

1. 修改前基线：`go test ./proxy ./config` 通过。
2. 新回归测试在修改生产代码前失败：缺失版本被判为 unsupported_model；带日期的点号/横杠别名产生不同指纹；Opus 5.5 长输入无法冷写。
3. 修复后定向测试通过。现有 12 个目标模型和对应 21 个名称均覆盖；额外覆盖未来数字版本、日期/包装前缀和非法名称。
4. 三种协议 `/v1/messages`、`/v1/chat/completions`、`/v1/responses` 的 JSON/SSE 共 24 个组合通过，测试了自定义映射别名与标准横杠名称之间复用、首次写入、重复读取、追加写入、0% 关闭。
5. `go test ./... -json` 退出码 0：544 个顶层测试和 429 个子测试通过，无失败。测试包 auth、config、pool、proxy 全部通过，其余包无测试。
6. `go vet ./...`、`go build ./...`、`git diff --check` 均退出码 0；两个 locale JSON 文件解析通过。

所有协议测试的上游由本地 httptest 服务器提供，没有为验证发送线上计费推理请求。此次未运行新的生产缓存命中测试或 Linux 镜像测试；上线前仍需部署验证。

## 差异自查

生产变更仅涉及缓存识别、缓存指纹规范化和两条诊断标签。规范化通过浅拷贝 Claude 请求、局部变量处理 Kiro payload，未原地修改上游请求。旧模式不进入新的规范化路径。未包含密钥、请求正文或线上数据，未改动账号并发、倍率、分组、Key 比例或路由目标。
