# 前缀准入修复：本地验证

日期：2026-10-18。规则版本：`prefix-total-v7`。

修复后，`prefix_total` 的比例不再成为每次请求固定的 Token 预算。系统按模型和候选前缀指纹浮动阈值并稳定决定新写入是否准入，因此同一稳定前缀不会因未缓存尾部变化而改变结果。后台比例大于 0 时，旧的未过期匹配继续读取，即使新写阈值恰好浮动到 0；通过的新断点完整写入，追加内容只写新尾部。拒绝新尾部时，旧读取仍保留，只有新尾部计为普通输入。诊断原因 `cache_admission_miss` 标明该情况。

修复前截图中重复前缀每轮固定留下约 10% 普通输入，是旧预算公式直接把 90% 分给读写造成的。本修复不再让同一内容因该比例每轮固定产生相同普通输入残差。比例现在是跨内容断点的准入参考，单个固定内容可能整段准入或不准入；实际按 Token 加权的缓存率不保证等于设置值。它仍是 Kiro 本地统计模拟，不是上游缓存遥测。
