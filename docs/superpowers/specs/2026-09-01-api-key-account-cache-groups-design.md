# API Key 账号分组与缓存策略设计

## 目标

支持创建多个对外 API Key。每个 Key 可以拥有独立的缓存模拟策略，并绑定一组 Kiro 账号。请求通过哪个 Key 鉴权，就只从该 Key 的账号组中选择账号，同时使用该 Key 的有效缓存策略。

## 数据模型

- `config.Account` 新增可选 `apiKeyId` 字段。
- `apiKeyId` 为空的历史账号在配置加载时迁移到现有第一个启用 API Key（当前为 `kiro`），并持久化迁移结果。
- API Key 的缓存字段继续使用现有可选覆盖字段：启用、模式、统一比例、创建比例、读取比例。未设置的字段继承全局默认值。
- 保留全局缓存默认值，默认启用、`uniform`、比例 1.0；比例允许 0 到 1，表示 0% 到 100%。

## 请求路由

- 鉴权上下文提供 API Key ID。
- 账号池新增按 API Key 过滤的选择方法；Claude、OpenAI Chat、OpenAI Responses 和 web-search 路径全部使用该方法。
- 当 API Key 没有绑定账号时返回现有的“无可用账号”错误，不跨 Key 借用账号，避免额度和缓存串用。
- 缓存 tracker 的账号隔离继续保留；同一 API Key 下不同 Kiro 账号仍分别维护缓存命中状态。

## 管理页面

在现有 API Key 列表中，每个 Key 卡片增加：

- 缓存模拟开关和模式选择。
- `统一比例`，或独立的`创建比例`与`读取比例`。
- “继承全局默认”操作，清除该 Key 的覆盖配置。
- 绑定账号数量和账号多选/绑定入口。

账号新增、编辑表单增加“归属 API Key”下拉框，支持选择未绑定或某个 Key。保存账号时同步更新 `apiKeyId`。

## API 与错误处理

- 扩展 API Key 创建、更新、查看 DTO，已存在的缓存字段继续使用 camelCase。
- 扩展账号创建、更新、查看 DTO，暴露 `apiKeyId` 和绑定 Key 名称。
- 更新账号归属时先校验 Key 存在且启用状态可被选择；保存失败回滚内存状态。
- 清除 Key 覆盖配置使用显式动作，不依赖 JSON `null` 和旧对象复制语义。

## 测试与发布

- 配置测试覆盖历史账号迁移、Key 覆盖继承和清除。
- Pool 测试覆盖按 Key 过滤、无绑定账号和排除重试。
- Handler 测试覆盖三种协议传递 Key ID，以及缓存 usage 只在成功响应后更新。
- 页面通过现有静态资源检查；完整发布前运行 `go test ./... -count=1`、`go build ./...` 和 `git diff --check`，再构建并健康检查 Docker 服务。
