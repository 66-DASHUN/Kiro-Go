# 参考 linapi 的前缀读写模拟

用户已选择新增前缀读写模式并作为默认，仅优化 Kiro，不修改 Sub2API。本轮实现并验证代码；线上切换沿用 Kiro 专属发布流程。

## 依据与限制

只读查询 Sub2API 的 https://linapi.org 账号（5683）最近 5,000 条记录。样本中长请求的读取比例不超过 95%，冷请求通常将整个可缓存前缀计入写入，温请求中读取之外仍有写入；例如总输入 96,016 = 普通 180 + 读取 91,044 + 写入 4,792。这只是供应方返回的用量表现，不能由账单日志还原其内部算法，也不能证明是 Claude 官方真实缓存。

采用它的拆分表现，不照搬普通输入固定 2 或 4、特定模型的绝对数值、历史账单或者第三方私有算法。所有总输入仍由已部署的离线 BPE/正原生 usage 决定。

## 策略

新增 `prefix` 模式；保留 `uniform` 和 `independent` 的原比例含义。新配置与缺省 mode 默认 prefix、参考读取比例 95%。已有明确保存的旧模式不静默更改；发布到用户当前 Kiro 时应明确将全局与现有 Key 的 mode 切为 prefix，保留原统一比例（90% / 95%）或独立模式的读取比例。账号、Key、禁用状态、绑定、端口和并发不变。

设完整输入为 T，最后可缓存断点为 C，实际未过期匹配的前缀为 M，则：

- 读取 R = floor(M × 内容驱动参考比例)，不超过 floor(0.95 × C)。
- 写入 W = C − R，包含新前缀以及模拟未读取的可缓存部分。
- 普通输入 I = T − C。始终 I + R + W = T；输出单独计算。
- prefix 模式的比例只控制读取，创建/读取独立比例字段在此模式下不生效。0% 表示读取 0、可缓存前缀全部写入；关闭模拟才使读写均为 0。
- 参考值在 [0,95%] 内限制，内容变化范围为 [max(0,参考−5%), min(95%,参考+5%)]；95% 时范围是 90%–95%，80% 时是 75%–85%，0% 保持 0。相同输入稳定，真实前缀匹配不足时读取率自然更低。
- 短输入、无可缓存断点、禁用、账号隔离、过期与成功才更新规则保持。5m/1h 写入明细按未读取区间对应的断点 TTL 分配。

## 内容计数

Claude 指纹仍含 model/role/tools/上下文等语义，指纹 JSON 元数据计数为 0；tools、system、消息使用与输入估算相同的内容计数。计费头不参与缓存指纹，也不分配进可缓存前缀，但仍留在完整输入中。完整语义输入作为正原生 usage 的归一化基准。

OpenAI/Responses 对翻译后 payload 的内容、工具参数与结果逐段计数，仅以传输无关的 JSON 生成指纹。总输入与 profile 断点仍统一归一化；不将随机 transport ID 或 JSON 包装计入内容。现有多模态近似边界保留，不声称视觉 Token 精确。

## 快照与 UI

请求发出时记录匹配前缀、可缓存总量、读取比例及 prefix 标识。完成时只按最终正原生 usage 缩放这一快照，不重新读取缓存条目；缩放后再次按 C−R 派生写入并重算 TTL 明细。托管搜索继续逐轮快照汇总。

全局和每 Key 编辑器加入前缀读写选项与说明，prefix 下比例框表示读取参考比例，两个旧独立比例框禁用。列表摘要显示前缀读取参考值，保存/重载不回退到旧模式。中英文同步。

## 验收

冷请求 R=0/W=C；完整重复 R 在配置范围内/W=C−R；追加消息只匹配旧内容；内容改变、过期、换账号不会伪造命中。显式断点外内容为普通输入。多 Key 比例与关闭状态有效。原生总输入变大/变小仍守恒，TTL 明细之和等于 W。Claude/Chat/Responses 的 JSON/SSE 均覆盖；原旧模式回归通过。
