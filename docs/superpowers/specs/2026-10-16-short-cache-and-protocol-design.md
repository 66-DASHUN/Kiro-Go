# 短输入缓存与协议能力核查

用户要求短输入参与模拟，同时改善真实能力和 cctest 兼容性。此次范围仅 Kiro 代码；不修改 Sub2API 或线上其他服务，不承诺测试分数。

## 缓存规则

- `prefix_total` 对所有已识别 Claude 家族使用相同规则：非空输入即可参与；模型名称只保留为隔离身份，不再分配 1024/4096 的长度门槛。
- 首次成功请求写入；有效期内相同前缀读取已提交份额；追加只给新增区间分配缓存份额。失败请求不提交。
- 新区间参考后台比例，按内容确定性浮动，比例上限仍为 95%。整数 Token 采用最近整数（误差不超过 0.5 Token）；极短输入的显示比例可能为 0% 或 100%，不人为扩大完整输入。
- 比例 0 完全关闭读写，不创建隐藏条目。普通输入 + 缓存读取 + 缓存创建 = 完整输入，5m + 1h = 创建量。
- 断点、TTL、20 块回看、账号和模型隔离、原生 Token 校准、已提交份额稳定语义保留。旧模式保留兼容行为。

## 能力核查

截图报告为 59%，失败项：签名、工具调用、WebSearch、结构化输出；流式 5/10。它是协议和能力混合检测，不是智力百分比。

检查请求字段是否丢失、工具 schema 是否被改变、SSE 是否遵循结构、搜索是否走实际服务、模型路由和思考强度是否传递。只修复有源码及回归用例支持的缺陷。官方签名缺失不本地伪造；不插入检测专用答案或身份提示词。

上游实测补充：原生 adaptive 请求确实返回独立的 `reasoningContentEvent.signature` 字符串事件，原适配层会丢弃它。因此新增原样透传，保留每段思考及其签名的对应关系；未验证其官方密码学有效性，不能生成替代签名。

## 协议实现决策

- 仅对模型元数据实际声明的字段转发 `thinking`、`max_tokens`；启用原生思考时不再插入固定 200000 的思考提示。旧模型保留兼容路径。
- 区分 `xhigh` 和 `max`。老 schema 仅有 max 时保留 xhigh 别名兼容，不再让同时声明两级的模型把 max 降为 xhigh。合并附加字段，避免互相覆盖。
- `output_config.format` 的 JSON Schema 通过指令和本地验证适配。生成指令位于提示过滤之后，并计入输入估算与缓存指纹。Schema 编译或类型非法在请求前返回 400；禁止加载外部文件/网络引用。
- 结构化输出缓冲完整答案后校验；不合格返回 502，不伪造字段、不自动重试。真实上游消耗记一次，错误标记为失败。工具调用与 max_tokens 中断可以在最终答案之前返回，不错误宣称它们已符合最终 Schema。
- 结构化 SSE 等校验完成后发送；普通流式路径保持增量输出。补齐 message_delta.stop_sequence，空 thinking 块保留 thinking 字段。真实签名在 content_block_stop 前以 signature_delta 发送。

## 验证

先添加短输入失败用例，覆盖 1、2、3、10、100、1023、4095 Token，首次/重复/追加/过期/零比例/失败未提交/原生校准。通过三种协议的 JSON/SSE 回归和全量 Go 测试、vet、build。协议修复分别添加能够验证请求或响应行为的回归用例。无真实报告复测时明确尚未验证分数。
