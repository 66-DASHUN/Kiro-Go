# 缓存模拟模型家族识别

用户已授权完善现有映射模型的缓存模拟。当前总缓存模式只维护四个版本，导致 Opus 5.5 等可正常调用的名称被判为 unsupported_model。修复仅在本地 Kiro 源码完成，本次不部署、不修改 Sub2API 或线上 Key 设置。

采用 Claude 家族模拟默认门槛：Sonnet 1024、Opus 4096、Haiku 4096。这是本地模拟策略，不宣称是这些版本的官方缓存遥测或官方门槛。合法数字版本自动适用家族默认门槛，保留日期、latest、thinking 后缀支持；未知家族和明显无效名称仍不生成模拟缓存。

总缓存模式的模型身份在缓存内部统一小写、首尾空白、anthropic. 前缀和版本中的点/横杠，避免同一模型改写名称后丢失旧前缀。保留不同模型家族、版本、日期以及思考配置的隔离，不改变转发给上游的模型名称。调用端自定义别名继续先由既有路由解析，不另建第二套路由映射。

比例仍由各 Key 的原设置决定；冷请求只写、完整重复只读、追加只写新增部分。TTL、短输入门槛、成功后保存、旧份额稳定、输入守恒、未知模型保护保持有效。旧模式不改语义。

验证：现有21项映射、未来数字版本、日期/点号/横杠别名、短输入边界、首次/重复/追加、跨模型隔离及三种协议的JSON/SSE。所有上游回复在本地测试服务器提供，不发送计费请求。
