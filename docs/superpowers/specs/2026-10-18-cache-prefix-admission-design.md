# Kiro 前缀缓存准入规则

日期：2026-10-18。规则版本：`prefix-total-v8`。本规则只调整 Kiro 的 `prefix_total` 本地模拟，不修改 Sub2API、线上配置或历史账单。

## 规则

后台比例控制冷前缀是否准入缓存，不作为每次请求的读写 Token 预算。冷请求没有任何有效旧前缀命中时，按模型与候选前缀内容指纹计算稳定、可复现的准入结果；比例是不同内容前缀之间的参考概率，同一内容不会因每次请求而重新随机。

后台比例大于 0 时，先查找账号隔离、模型一致且未过期的缓存前缀。只要有有效旧前缀命中，读取该旧前缀；如果当前有效缓存断点比命中位置更长，则将命中位置之后的整个可缓存尾段计为缓存创建，不再对尾段进行第二次比例抽样。比例为 0 或模拟关闭时不读、不写，也不续期已有条目。完整重复只读不写。只在上游成功后提交或续期。

设完整输入为 `T`，有效缓存断点累计为 `C`，匹配旧前缀为 `M`，旧条目保存的读量为 `S`，是否命中任何有效旧前缀为 `H`，冷前缀准入结果为 `A`：

```text
R = min(S, M)
W = C - M,  if C > M and (H or A)
W = 0,      otherwise
I = T - R - W
```

比例为 0 或模拟关闭时，`R=W=0`，不读取、不写入、不续期已有条目。模型门槛、断点覆盖、TTL、账号隔离、成功后提交和请求级计数校准继续生效。任何时候都要求 `I+R+W=T`、`W5m+W1h=W`，输出 Token 独立。

## 行为边界

命中后自动写入新增尾段，避免一个已有长缓存会话因为尾段的独立概率拒绝而把新上下文记为普通输入。设置比例只影响冷前缀，因而不保证按 Token 加权后的总缓存率恰好等于设置值。缓存读取仍只由实际已存且未过期的匹配条目决定；本地模拟不等同于上游遥测或 Sub2API 的精确 Token 结果。

诊断规则版本为 `prefix-total-v8`。`cache_admission_miss` 只表示没有任何有效旧前缀命中时，冷前缀未准入；这种情况下新内容全部计为普通输入且不会建立缓存条目。有效旧命中后存在新增尾段时，诊断中的读取和创建都应保留，普通输入只包含断点未覆盖部分。

## 验收

- 冷前缀通过比例准入时完整写入；拒绝时不读、不写且不建立隐藏条目。
- 重复同一已缓存内容只读不写，且读取量不超过条目记录的缓存份额。
- 已有有效前缀后追加内容：读取旧前缀，并将新增可缓存尾段完整计为缓存创建；提交成功后下次请求可读到扩展前缀。
- 新尾段即使按冷前缀阈值会被拒绝，只要有有效旧命中，也必须创建尾段缓存。
- 内容和模型变化：冷准入由指纹决定；账号、模型或指纹不同不能复用条目。
- 0% / 关闭：不读写、不续期、不建立隐藏条目。
- 原生 Token 校准、TTL、短输入、流式与非流式响应保持输入守恒和 TTL 分项守恒。
