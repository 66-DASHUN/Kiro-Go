# Kiro 前缀缓存准入修复

日期：2026-10-18。此规则取代 v5 中把比例直接换算成每次请求 Token 预算的算法。只调整 Kiro 的 `prefix_total` 本地模拟，不修改 Sub2API、线上配置或历史账单。

## 规则

后台比例是新缓存断点的内容准入参考，不是每次请求的读写 Token 配额。每个候选断点的比例浮动和确定性准入都只使用模型标识与该断点的内容指纹；同一前缀即使追加不同的未缓存尾部，准入结果仍相同。不同前缀可得到不同有效阈值与准入结果，不使用每次独立随机数。

后台比例为正时先查找账号隔离、模型一致且未过期的缓存前缀；正比例的读取不受内容浮动阈值影响，即使本次新写阈值浮动到 0，旧命中仍照常读取。比例为 0 或模拟关闭时不读、不写，也不续期已有条目。若请求有未命中的新尾部，仅当候选断点通过其前缀阈值准入时，才将该段完整计为写入；未通过则保留旧读取，并将新增尾部计为普通输入。冷请求通过准入时完整写入有效前缀；完整重复只读不写。只在上游成功后提交或续期。

设完整输入为 `T`，有效缓存断点累计为 `C`，匹配旧前缀为 `M`，旧条目保存的读量为 `S`，本次新尾部准入结果为 `A`：

```text
R = min(S, M)
W = C - M,  if C > M and A
W = 0,      otherwise
I = T - R - W
```

比例为 0 或模拟关闭时，`R=W=0`，不读取、不写入、不续期已有条目。模型门槛、断点覆盖、TTL、账号隔离、成功后提交和请求级计数校准继续生效。任何时候都要求 `I+R+W=T`、`W5m+W1h=W`，输出 Token 独立。

## 行为边界

整段前缀准入避免对同一个稳定前缀每轮固定留下 `1-p` 的普通输入。代价是单个内容样本可能整段准入或整段未准入；设置比例表示跨不同内容前缀的参考准入率，不保证按 Token 加权后的总缓存率恰好等于该值。缓存读取只由实际已存且未过期的匹配条目决定。

诊断规则版本为 `prefix-total-v7`。新增 `cache_admission_miss` 原因表示新尾部未准入；若存在旧命中且后台比例为正，诊断中的读取仍应大于零。无命中时新内容全部计为普通输入，且不会建立缓存条目。

## 验收

- 重复同一内容：准入结果稳定；冷请求通过时完整写，热请求完整读且不重复写。
- 改变尾部：旧的未过期前缀仍可读；尾部按其断点单独准入，通过时只写尾部，未通过时只把尾部记为普通输入。
- 内容和模型变化：准入由指纹决定；账号、模型或指纹不同不能复用条目。
- 0% / 关闭：不读写、不续期、不建立隐藏条目。
- 正比例但新写阈值浮动为 0：仍读取未过期的匹配前缀。
- 相同候选前缀与不同未缓存尾部：写入准入结果相同。
- 原生 Token 校准、TTL、短输入、流式与非流式响应保持输入守恒和 TTL 分项守恒。
