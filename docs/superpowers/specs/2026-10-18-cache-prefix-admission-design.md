# Kiro 前缀缓存准入规则

日期：2026-10-18。规则版本：`prefix-total-v10`。本规则只调整 Kiro 的 `prefix_total` 本地模拟，不修改 Sub2API、线上配置或历史账单。v10 移除把后台比例当成单请求 Token 预算的错误逻辑。

## 规则

后台比例表示冷前缀的缓存准入参考概率，不表示每次请求要把多少 Token 切成缓存。系统根据内容指纹稳定决定一个完整冷前缀是否准入；比例按前缀确定性上下浮动，最多五个百分点，例如 80% 对应 75%–85%，95% 对应 90%–95%。同一账号、内容和设置下结果稳定。100% 明确允许所有有效冷前缀准入。这个比例是准入率，不保证某个账号单条或短期的 Token 加权缓存率恰好等于设置值。

设完整输入为 `T`，最后有效缓存断点累计 Token 为 `C`，本请求匹配的旧前缀长度为 `M`，该条目实际保存的份额为 `S`，冷前缀准入结果为 `A`，是否存在有效且未过期的前缀命中为 `H`：

```text
R = min(S, M),                 if H
R = 0,                         otherwise
W = max(C - M, 0),             if H
W = C,                         if not H and A
W = 0,                         if not H and not A
I = T - R - W
```

冷前缀准入后，完整缓存到最后有效断点 `C`；没有有效断点覆盖的尾部 `T-C` 仍是普通输入。命中时读取已保存份额，并只把最后命中断点之后的新稳定尾段写入缓存；完全重复的内容不会重复创建缓存。未准入的冷前缀不会读写，也不会建立隐藏条目。任何时候都要求 `I+R+W=T`、`W5m+W1h=W`，输出 Token 独立。

比例为 0 或模拟关闭时，`R=W=0`，不读取、不写入、不续期已有条目。模型门槛、断点覆盖、TTL、账号隔离、成功后提交和请求级计数校准继续生效。比例只控制冷前缀准入；只要比例大于 0，命中的有效缓存仍按保存份额读取，即使当前比例低于创建它时的比例。

## 行为边界

`cache_admission_miss` 只表示没有有效旧前缀命中且冷前缀未准入；这时缓存读写为零，所有输入都保留为普通输入。命中后新尾段随已命中的前缀生命周期一并准入，避免把同一稳定内容每轮重复拆成普通输入与缓存输入。缓存数字是 Kiro 本地估算，不是上游遥测或 Sub2API 的精确 Token 结果；没有上游缓存遥测时，Token 数仍受本地 Token 估算和断点识别精度影响。

诊断规则版本为 `prefix-total-v10`。诊断记录完整输入、有效缓存长度、匹配位置、已保存份额、准入参考比例、读写量、普通输入和限制原因。兼容字段 `budget` 仅表示本次读写 Token 之和，不是截断上限。

## 验收

- 每个稳定冷前缀的准入结果可重复；跨大量不同前缀的准入率接近后台比例及允许的浮动范围。
- 已准入冷前缀完整写至有效断点，重复热请求完整读取已保存份额，输入账目守恒。
- 追加内容时读取已保存旧前缀，只写新的有效尾段；完全重复不创建缓存，未覆盖断点的尾部保留普通输入。
- 被拒绝的冷前缀不读写、不建立隐藏条目；已有有效匹配仍可读取。
- 内容、模型或账号隔离、原生 Token 校准、TTL、短输入、流式与非流式协议均保持守恒。
- 0% / 关闭不读写、不续期、不建立隐藏条目；100% 按显式配置允许全缓存。
