# 通用模型缓存模拟设计

用户已在“以后新增模型”讨论后授权继续优化。沿用已有隔离分支与仅 Kiro 部署流程。

## 行为

`prefix_total` 对经过现有路由、兼容现有生成接口的任何非空模型标识应用有效 Key 的后台策略。模型发现与账号权限继续来自动态上游模型列表；实际生成成功才提交模拟缓存。列表暂未刷新不应导致一个已成功调用的模型被排除，因此缓存内部不再另设家族或版本白名单。

新输入按后台参考比例及内容确定性浮动分配，非空输入门槛为 1；命中有效前缀读取已保存份额，追加只写新增区间，5m/1h 和完整输入保持守恒。0% 和关闭不产生缓存。未知或无权限模型由现有账号路由和上游拒绝，失败请求不提交缓存，也不返回成功的模拟计费结果。

## 身份与兼容

缓存身份使用实际映射后的模型。现有 Claude 数字版本点号/横杠/anthropic. 包装兼容继续保持；其他模型仅统一首尾空白和大小写，保留点号、横杠和供应商前缀，避免将不同模型误合并。不改变实际发往上游的标识或账号路由。

保持现有账号隔离；不同模型、版本、工具和思考参数继续通过缓存指纹隔离。不在这次更改现有用户隔离语义、Key 模式/比例、账号绑定、并发、Sub2API 或旧缓存模式。

## 可观测性和边界

规则版本升级为 `prefix-total-v4`。空模型诊断使用 `empty_model`，说明文字不再声称只支持 Claude 家族。此项是本地用量模拟，不代表上游真实缓存、自动支持新协议或提高模型能力。新的响应格式、全新工具或思考参数仍可能需要协议适配。

## 验证和发布

先以新的 GPT/Qwen/DeepSeek/MiniMax/GLM/Kimi 与虚构未来模型复现当前无缓存，再实现通用规则。验证长短输入冷写/热读/追加、过期、0%、失败、三协议 JSON/SSE、Key 覆盖、跨模型与账号隔离、Claude 别名兼容和非 Claude 标点隔离。运行 Go 全量测试、vet/build，独立代码审查后推送。资源受限 Linux 构建/并发检测、独立数据候选探针通过后，仅切换 Kiro；保留一致性数据备份和旧容器，验证公网/内部别名及其他容器基线。
