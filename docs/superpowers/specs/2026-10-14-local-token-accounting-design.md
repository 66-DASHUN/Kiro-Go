# 纯本地 Token 与缓存模拟计数

用户已确认无需官方 API Key，采用纯本地模拟，并授权实施。本次仅实现、验证和提交，不推送或部署。

## 目标与边界

输入、输出以及缓存前缀采用同一离线 BPE 计数器。上游含义明确且为正的原生输入/输出 Token 继续优先；原生字段缺失时仅使用可见请求和实际回答的本地计数，不再用 contextUsagePercentage 回填输入。上下文占用继续保留为上游诊断事件。

保留 API Key 独立缓存比例、±5 个百分点的内容驱动变化、按真实账号隔离、TTL、成功才更新缓存、所有既有接口、账号配置和并发限制。缓存仍为本地模拟，不宣称 Claude 官方精确分词或真实缓存。

## 计数器

采用 github.com/tiktoken-go/tokenizer v0.7.0 的 o200k_base，词表编译进 Go 程序，不需要官方 Key 或运行时下载。该版本兼容现有 go 1.25 模块。初始化一次，文本、JSON schema、工具参数均使用同一 Count。

长文本按不超过 4096 字节的 UTF-8 安全边界分块，优先使用近端空白边界，避免第三方 BPE 在极长连续片段上的二次复杂度。分块仍属于本地近似，不能承诺官方误差范围。计数异常回退原字符估算，不丢弃请求内容。

输入包括 system、全部历史消息、工具定义、工具结果及当前正文。输出包括可见回答、实际思考和工具调用。保留当前多模态估算行为；本次不声称图片、PDF 的视觉 Token 精确度。

OpenAI/Responses 注入的思考提示词也计入本地输入。托管联网搜索逐轮保留原生值或本地回退，统计隐藏工具输出以及携带工具结果的后续输入，逐轮缓存快照归一化后汇总读写，全部调用成功返回后统一保存缓存，MCP 取消或后续轮次失败不写入。当托管搜索与客户端工具同时出现时，返回给客户端的代理生成结果正文也计入对应轮次的本地输出回退，正原生输出仍优先。Claude/Chat 的流式正文缓冲区只记录正文，避免工具名称/参数在正文和工具列表重复累计。

## 统计与缓存

移除 finalizeUsageTokens 的上下文参数及所有调用方对上下文占用的输入换算。保留原生 Token 优先和本地输入/输出兜底，覆盖 Claude、Chat Completions、Responses 及搜索循环。

Claude 缓存 profile 必须尊重调用方提供的正输入总量，不能被指纹 JSON 包装长度抬高。指纹和 TTL 行为保持，累计断点按同一总量归一化，最终普通输入、读取、创建非负且三者之和等于最终输入。上游真实输入覆盖本地估算时，仍允许缓存按这个真实输入总量缩放；上下文百分比不再参与缩放。

## 验收

- hello 为 1 Token，100 个空格分隔 hello 为 100 Token；同一 BPE 引擎用于请求及回答。
- 模拟上下文从约 4000 增至约 5000 时，固定正文的输入 Token 不变，输出随实际回答增长。
- 三种协议、流式与非流式均不出现上下文回填；短输入无模拟缓存。
- 长输入冷请求读取 0、重复请求读取大于 0；不同 Key 比例有效；输入三项守恒。
- count_tokens 与消息接口的本地输入计算一致。
- 完整 Go 测试、vet、构建，以及针对新增计数器/缓存/协议用量的 race 检查通过。

只改变新请求统计，不回写历史账单或账号使用量。后续部署会因进程重启自然清空旧内存缓存，但本轮不操作线上实例。
